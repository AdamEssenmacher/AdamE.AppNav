# AdamE.AppNav 0.1.0-preview.1

[Documentation home](../index.md) | [All release notes](index.md)

This is the first public preview of AdamE.AppNav: a MAUI-first navigation framework whose planning, policy, logical
state, history, diagnostics, and orchestration remain independent of any UI host.

## Supported platforms

- .NET 10 with SDK `10.0.403` and workload set `10.0.402.1`.
- Android API 28 and later.
- iOS 15 and later.
- Mac Catalyst 17 and later.

Windows, a production Blazor adapter, true multi-window MAUI presentation, transitions, and NuGet.org publication are
outside this preview.

## Golden MAUI path

- Register generated routes, a stack or branch-host navigation model, and generated pages with `AddAppNav`.
- Navigate through `IRouterNavigator` using full request envelopes or its four typed route extensions.
- Use `FallbackRouteFactory` for the common typed startup fallback, or the mutually exclusive advanced request factory.
- Start attached MAUI navigation with the observed synchronous `Start(window, windowId)` helper; `StartAsync` remains
  available for tests and explicit coordination.
- `Auto`, `Contextual`, `ReplaceCurrent`, and `Canonical` now have standardized planning semantics.
- Branch hosts render as tabs by default and can be mapped independently to the built-in flyout or an
  application-owned `IMauiBranchHostFactory`; factories declare placement capabilities and participate in
  presentation verification, rollback, and disposal.

## Security and deferred navigation

- External lifecycle ingress is opt-in through `UseAppNavExternalNavigation` and requires at least one trusted origin.
- URI trust checks include normalized scheme, IDN host, effective port, credentials, length, and absolute/root-origin
  validation before matching, persistence, analytics, or application policy.
- Bootstrap and runtime ingress queues are bounded, drop their oldest entries on overflow, and use non-blocking tail
  retries with expiry and terminal-failure classification.
- Deferred persistence uses schema 3 and stores only the canonical route URI, source, disposition, timestamp, window ID,
  restorable metadata, and provenance provider. It never stores raw transport URIs, referrers, correlation IDs,
  arbitrary provenance attributes, or cold-start state.
- Schema-2 data is deliberately reset once. Future-version data is quarantined intact for downgrade safety.

## Adapter boundary and generation

- Core supports window, stack, branch-host, and modal topology and rejects unknown node shapes before presentation.
- The MAUI presenter rejects multi-window plans before native mutation and enforces its attached window identity.
- Route generation remains in `AdamE.AppNav.Generators`; MAUI page discovery and `APPNAV020`–`APPNAV025` move to
  `AdamE.AppNav.Maui.Generators`. Each package carries only its assigned analyzer.
- A core-only adapter contract suite exercises every supported node shape, atomic commit behavior, cancellation,
  reconciliation, shutdown, and event detachment through public APIs.
- Host reconciliation is conditional on the state the host changed from. A reconciliation whose base is no longer
  current is rejected before presentation with `StaleNavigationReconciliationException` and a `ReconciliationRejected`
  diagnostic.
- Core owns [route-entry leases](../advanced/entry-leases.md): one per entry occurrence, opened by the application
  before it navigates or by the adapter during presentation. A lease retires on the commit that drops its entry, when
  its request ends without committing it, by the application, by its parent, or at shutdown, and is released only
  once its opener has closed it and no native artifact, child, or pending work holds it. Router disposal waits for
  every release; only `DisposeAsync` waits, and synchronous `Dispose` returns at once.
- An application closes a lease it sends once the request has ended, in a `finally` block; a lease closed before it
  is sent is refused. A lease an adapter opens with `GetOrOpen` is closed by core when that operation ends, so the
  adapter attaches what the entry borrows during that operation. `GetOrOpen` refuses a registry that serves no router,
  and opens a lease only while the router is presenting; outside `ApplyAsync` it returns an existing lease or throws.
- When router disposal is still waiting for leases after `EntryLeaseShutdownWarningDelay` (five seconds by default), it
  writes an `EntryLeaseShutdownWaiting` warning saying what holds each lease, and keeps waiting. MAUI apps set the
  delay with `AppNavNavigatorOptions.EntryLeaseShutdownWarningDelay`.
- A host that cannot run a lease's `OnRetired` work is a fatal failure, like a release it cannot run: the lease and its
  ancestors keep their resources. Retirement work that runs and throws is still a survived defect.
- `IRouteEntryLeaseHost.InvokeAsync` must complete only after the work it was given has. Core checks this: a task that
  completes early is a fatal host failure, and the work's own exception reaches core even if the host swallows it.

## Breaking preview changes

- `UseAppNavAppLinks` is replaced by `UseAppNavExternalNavigation`.
- `IMauiExternalNavigationDispatcher.Dispatch` is replaced by `TryDispatch`, which reports whether a request was
  accepted.
- URI/source convenience overloads are removed from the navigator surface; external boundaries construct the complete
  `RouterNavigationRequest` envelope.
- `NavigationNode` is no longer externally derivable.
- `NativeBackGesture`, `TabChanged`, and `NativeReconciliation` are renamed to `HostBack`, `BranchChanged`, and
  `HostReconciliation`, respectively, while retaining their numeric values.
- A non-null `ActiveWindowId` must identify an existing window; there is no silent fallback.
- `NavigationReconciliation` takes a required `BaseState` before `TargetState`, which the router compares by
  reference with `CurrentState`. There is no unconditional reconciliation; pass `navigator.CurrentState` when the host
  has nothing more specific.
- With `UseScopedPages`, the MAUI page factory creates one DI scope per route-entry occurrence, owned by the lease it
  opens for the entry, instead of one per page. A page rebuilt for a still-committed entry shares its scope, and the scope is
  disposed after the commit that drops the entry rather than when its page is released.
- Entry IDs must now be unique across the whole navigation state, not just within one stack. `AddAppNav` always
  configures route-entry leases, which are keyed by entry ID, so the router rejects a plan that repeats an ID anywhere
  (another tab, a modal, another window) with `AppNavigationConfigurationException`, before presentation. There is no
  opt-out. An app whose `EntryId` factory derives the ID from the route alone, and shows the same route in more than
  one tab, makes the ID include where the entry lives: carry the tab in the route (`SettingsRoute(string Tab)`) and
  use `.EntryId(route => $"{route.Tab}/settings")`, so each occurrence gets its own lease and DI scope.
- Scoped `IMauiRoutePageLifecycleHook` instances now come from the entry's scope, so the old and new pages of a rebuilt
  entry share one hook, and it can see `OnPageCreatedAsync` for the new page before `OnPageReleasedAsync` for the old.
- Page scopes are disposed on a later main-thread turn, never inside the navigation that dropped the entry, and
  `AppNavRuntime.DisposeAsync` returns only once every lease has been released, which needs the main thread to keep
  running. It has no timeout.
- When the application opens an entry's lease itself, the MAUI page factory leaves the entry's resources to it and gives
  each page a scope of its own, as before.

## Validation and artifacts

The canonical deterministic gate is `eng/verify.sh release`. Release packages are built and validated before tagging,
then the tag workflow reuses those exact `.nupkg` and `.snupkg` artifacts, publishes SHA-256 hashes, and creates a GitHub
prerelease. It does not rebuild packages or publish to NuGet.org.
