# AdamE.AppNav 0.1.0-preview.1

This is the first public preview of AdamE.AppNav: a MAUI-first navigation framework whose planning, policy, logical
state, history, diagnostics, and orchestration remain independent of any UI host.

## Supported platforms

- .NET 10 with SDK `10.0.400` and workload set `10.0.302.1`.
- Android API 28 and later.
- iOS 15 and later.
- Mac Catalyst 15 and later.

Windows, a production Blazor adapter, true multi-window MAUI presentation, transitions, and NuGet.org publication are
outside this preview.

## Golden MAUI path

- Register generated routes, a stack or branch-host navigation model, and generated pages with `AddAppNav`.
- Navigate through `IRouterNavigator` using full request envelopes or its four typed route extensions.
- Use `FallbackRouteFactory` for the common typed startup fallback, or the mutually exclusive advanced request factory.
- Start attached MAUI navigation with the observed synchronous `Start(window, windowId)` helper; `StartAsync` remains
  available for tests and explicit coordination.
- `Auto`, `Contextual`, `ReplaceCurrent`, and `Canonical` now have standardized planning semantics.

## Security and deferred navigation

- External lifecycle ingress is opt-in through `UseAppNavExternalNavigation` and requires at least one trusted origin.
- URI trust checks include normalized scheme, IDN host, effective port, credentials, length, and absolute/root-origin
  validation before matching, persistence, analytics, or application policy.
- Bootstrap and runtime ingress queues are bounded, drop their oldest entries on overflow, and use non-blocking tail
  retries with expiry and terminal-failure classification.
- Deferred persistence uses schema 3 and stores only the canonical route URI, source, disposition, timestamp, window ID,
  restorable metadata, and provenance provider. It never stores raw transport URIs, referrers, correlation IDs,
  arbitrary provenance attributes, or cold-start state.
- Schema-2 data is deliberately reset once. Future-version data is quarantined intact for downgrade safety.

## Adapter boundary and generation

- Core supports window, stack, branch-host, and modal topology and rejects unknown node shapes before presentation.
- The MAUI presenter rejects multi-window plans before native mutation and enforces its attached window identity.
- Route generation remains in `AdamE.AppNav.Generators`; MAUI page discovery and `APPNAV020`–`APPNAV025` move to
  `AdamE.AppNav.Maui.Generators`. Each package carries only its assigned analyzer.
- A core-only adapter contract suite exercises every supported node shape, atomic commit behavior, cancellation,
  reconciliation, shutdown, and event detachment through public APIs.

## Breaking preview changes

- `UseAppNavAppLinks` is replaced by `UseAppNavExternalNavigation`.
- `IMauiExternalNavigationDispatcher.Dispatch` is replaced by `TryDispatch`, which reports whether a request was
  accepted.
- URI/source convenience overloads are removed from the navigator surface; external boundaries construct the complete
  `RouterNavigationRequest` envelope.
- `NavigationNode` is no longer externally derivable.
- `NativeBackGesture`, `TabChanged`, and `NativeReconciliation` are renamed to `HostBack`, `BranchChanged`, and
  `HostReconciliation`, respectively, while retaining their numeric values.
- A non-null `ActiveWindowId` must identify an existing window; there is no silent fallback.

## Validation and artifacts

The canonical deterministic gate is `eng/verify.sh release`. Release packages are built and validated before tagging,
then the tag workflow reuses those exact `.nupkg` and `.snupkg` artifacts, publishes SHA-256 hashes, and creates a GitHub
prerelease. It does not rebuild packages or publish to NuGet.org.
