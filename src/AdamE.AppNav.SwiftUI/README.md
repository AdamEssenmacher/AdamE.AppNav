# AppNav with SwiftUI and OAHU

The managed host targets .NET 11 for iOS. The Swift package provides an iOS 18+ renderer for one window with either a linear stack or a tab host, plus one sheet with its own stack. The probe builds against AppNav from this checkout and OAHU `0.1.0-preview.g7a56b3ba`.

## Integrate

1. Reference [AdamE.AppNav.SwiftUI.csproj](AdamE.AppNav.SwiftUI.csproj) from the iOS app or use the `AdamE.AppNav.SwiftUI` NuGet package. The package includes its SwiftPM manifest and sources under `native/Swift`. Add [the Swift package](Swift/Package.swift) to the app's OAHU screens package. When using a packed NuGet artifact, find the Swift package at `native/Swift` inside it. Both Swift packages resolve `OahuRuntime` from `OAHU_RUNTIME_SWIFT` when set. Otherwise they look for the pinned OAHU package under `NUGET_PACKAGES`, which defaults to `~/.nuget/packages`. Set `OAHU_RUNTIME_SWIFT` explicitly when the build process cannot see your configured NuGet package directory.
2. Set up OAHU screen generation for the app's contracts. Use the hosted `INavigationShellViewModel` contract or define a shell contract that delegates `Target` and `Report` to that model. In the Swift screen, translate these generated values to `NavigationProjection` and `NavigationReading`. [The example screen](../../prototype/Shell/ProbeScreens/Sources/ProbeScreens/Screens.swift) shows the mapping and a test-only footer. The app's mounted screens specify their own titles and toolbars.
3. Initialize `OahuScreens` before scene attachment. Create one `RouteEntryLeaseRegistry` with `SwiftUIRouteEntryLeaseHost`, pass that same registry to `RouterNavigatorFactoryOptions.EntryLeases` and `SwiftUINavigationHost.Attach`, and bind the `OahuNavigationPresenter` to the router. The factory callback takes a `RouteEntry`, its lease, and a flag for a lease opened during that call. It chooses the app screen and returns its `OahuMount` plus optional cleanup.
4. Set the scene window's root controller to the host's `ViewController` before navigating. If recreating a scene while retaining the router, attach its new host and call `RefreshPresentationAsync` so the new surface witnesses the retained state. On disconnect, call `Detach`, remove the controller from the window, and dispose the host on the main thread. Dispose the navigator asynchronously when its lifetime ends.
5. Send push, deep-link, and programmatic Back intents through the router. SwiftUI owns native tab selection and Back animations. The presenter reconciles native changes after the visible stack settles.

The factory may register entry-owned resources on an open lease. Use `AfterTeardown` for view models and other resources owned by a single mount, including when rebuilding a scene whose retained lease is closed. The host runs it after OAHU disconnects the mount and before detaching the lease. If the factory throws before returning, it owns cleanup for resources created during that call.

An app requiring a policy decision before Back may supply a `NavigationBackControl` to route selected entries through an AppNav Back command. For those entries the shell replaces the system Back button, and when one is the top of a sheet it disables interactive dismissal. The app should use the same managed Back command for any close buttons it adds to guarded screens. The default configuration observes native Back, including canceled edge gestures and the native Back-history menu.

## Native settling

By default the renderer assigns complete SwiftUI paths in an animation-disabled transaction. Set `animatesSinglePushes: true` on `NavigationShell` to animate a one-entry append to the settled visible stack. The app can then use SwiftUI's matched zoom source on the tapped cover and zoom transition on the mounted destination. The app supplies the row's press and selection appearance. A branch switch or multi-entry deep link still installs its complete path without stepping through intermediate destinations. It samples the active native controller stack across consecutive frames and verifies the mounted top, controller count, observed identities, and transition state. SwiftUI may materialize intermediate pages only when exposed by Back. The shell preserves its last witnessed path for an interactive cancellation and waits for sheet removal before reporting dismissal. While a revision applies, the shell withholds native Back and interactive sheet dismissal until the native stack settles. The one exception is Back on an animated one-entry push once its page is on screen. If a Back gesture or a pop from the Back-history menu makes UIKit give back an animated one-entry push before the shell settles it, the shell takes the shorter path at once. When UIKit's stack settles without the page, it reports the push and the shorter stack as a native Back together. A cancelled gesture puts the push back. SwiftUI no longer pushes the page again. The shell briefly withholds Back on a newly selected tab while AppNav accepts the selection. If a pop slipped through before a separate tab reading, the shell restores that tab’s intact stack so the selection can commit. Intermediate actions without an independent native reading cannot add a separate history entry. The controller lookup depends on SwiftUI's UIKit hosting hierarchy. The simulator demo covers iPhone navigation; it has no tests for iPad-specific navigation, split views, or physical devices.

The iPhone simulator suite covers canceled Back and multi-pop, a direct deep link and ordinary Back traversal, retained tabs, an animated push inside a sheet, modal dismissal, guarded Back, and the managed and native Home → Game pushes. It also exercises an animated sheet presentation and replacement of the SwiftUI hosting controller during a pending push. See the [test matrix and reproduction commands](../../prototype/SWIFTUI.md).

## Native transitions and destination chrome

Map the OAHU shell transition into `NavigationProjection.transition` for each projection. Its operation, source and destination entries, optional screen names, and source key are presentation metadata. The app chooses a shared key and namespace for the cover it marks with SwiftUI's `matchedTransitionSource`.

Pass `NavigationCustomization` when constructing `NavigationShell` to configure three native hooks:

- `transactionAnimation` returns a SwiftUI `Animation`, or `nil` for an immediate install. The renderer consults it for a verified one-entry push or pop in the visible branch or open sheet, a root-only sheet presentation, or an isolated sheet dismissal. The background branches and their mounts must remain unchanged during an in-sheet step. A new sheet with prebuilt history installs directly, as do multi-entry paths, branch switches, refreshes, rollbacks and host reattachment. The existing `animatesSinglePushes` option remains the default for pushes when a policy is omitted. User-initiated Back and sheet gestures keep their system animation.
- `transition` selects `.automatic`, `.zoom(sourceID:namespace:)`, or `.native(style)` for a destination. The native case accepts a SwiftUI `NavigationTransition` value. The shell attaches the style to the decorated page for a stack destination, or to the presented container for a sheet root. A style that does not need a matched view can run without a source key. A route-wide style can also configure a restored destination for a later native Back. The transaction policy still controls animation during installation. Use the dedicated zoom case with a matching `matchedTransitionSource` in the source view. Even for an immediate push, the renderer associates the push context with the exact source and destination mounts for native Back, preserves the departing view through the transition, and drops its origin after settlement. A replaced source or restore clears the corresponding match.
- `chrome` decorates the mounted view with app-owned SwiftUI presentation, such as the navigation title and toolbar. It runs when SwiftUI constructs the destination, including its initial transition build.

With the iOS 27 SDK, return `.native(.crossFade)` for a sheet root in an `if #available(iOS 27, *)` branch, then return `.automatic` on earlier releases. Enable animation for the isolated sheet presentation with `transactionAnimation`. Update any exhaustive switches over `NavigationDestinationTransition` to include the native case. [Apple’s crossfade example](https://developer.apple.com/documentation/swiftui/navigationtransition/crossfade).

When passing an already type-erased style that needs a matched source, set `requiresMatchedSource: true` so the shell checks for a live keyed origin. SwiftUI's type-erased value does not expose the underlying style.

The Fade Sheet demo crossfades on iOS 27.2. During the recorded presentation, three regions at different heights blend together over the same frames. In a separate iOS 27.0 comparison, both an AppNav push and a direct SwiftUI `NavigationLink` using `.crossFade` render with a horizontal slide. [Sheet recording](../../prototype/results/fade-sheet-ios27.mp4) · [Frame samples](../../prototype/results/fade-sheet-ios27.frames.txt).

The Game probe uses the hooks to choose a zoom from `game-cover` and attach the Game toolbar. Its comparison row uses a system view-destination `NavigationLink` inside the same typed stack. The Edit sheet uses the hooks to push Review from a matched source without changing the background branch. [SwiftUI probe](../../prototype/Shell/ProbeScreens/Sources/ProbeScreens/Screens.swift).
